# Principles, enforced

The roadmap says the principles are the pitch: security buyers only trust a manipulation-detection
company that is visibly incapable of being a manipulation company. A principle that exists only in
a slide is a promise; a principle with a failing test behind it is a property of the product. This
file maps each one to the mechanism and the test that holds it.

| #   | Principle                                                          | Mechanism                                                                                                                                                                                                                 | Enforced by                                                                                                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Defense only.** No tools to profile targets or influence people. | No API returns a person profile or influence recommendation. The engine's only output is an `Analysis` of a _request_.                                                                                                    | Code review rule for every new endpoint (from M2); contract clause (from v3). Not testable in M0 beyond principle 2.                                                                                                                                                                   |
| 2   | **Analyze requests, not employees.**                               | The domain model has no recipient, employee or per-person score fields. Routing an alert to a recipient is a connector concern and never enters the engine. Baselines are keyed on vendor, workflow or role.              | `packages/eval/test/principles.test.ts` ("no domain schema carries recipient identity or a per-person score") walks every zod schema in `@shield/shared`. `packages/db/test/schema.test.ts` scans the SQL migrations for person columns and allows `actor_ref` only in `audit_events`. |
| 3   | **Label the tactic, not the person.**                              | Explanations come only from each tactic's `explanation` template. The template names the tactic and quotes the request.                                                                                                   | `pnpm shield tactics lint` rejects person labels (`PERSON_LABELS` in `packages/tactics/src/lint.ts`) in names and explanations. The principles test checks every explanation the engine produces across the whole corpus.                                                              |
| 4   | **Precision first.**                                               | Requests without a high-risk action can warn but never pause. A pause needs two independent _pressure_ families or a named critical combination. Bank changes alone only warn. Shadow mode comes before enforcement (M4). | Principles test ("never pauses a request with no high-risk action"). The CI eval gate (`packages/eval/gate.json`) fails the build if PAUSE precision or the false-alarm rate regresses.                                                                                                |
| 5   | **Explain every flag.**                                            | Every fired tactic carries verbatim evidence and produces one explanation line. LLM hits without a verbatim quote are dropped.                                                                                            | Principles test ("every fired tactic gets an explanation with evidence"). `validateHits` in `packages/llm/src/validate.ts` and its tests.                                                                                                                                              |
| 6   | **The copilot leads through preparation, not exploitation.**       | Copilot track only (not in M0). Its memory stores only what the user authors, never inferred vulnerabilities, and a refusal eval suite runs in CI.                                                                        | Planned: `apps/copilot` refusal suite. See the roadmap's copilot section.                                                                                                                                                                                                              |

Two further properties are engineering commitments rather than roadmap principles:

- **The LLM cannot veto the rules.** Rule hits are merged with LLM hits by taking the maximum confidence. A model that has been talked out of a finding cannot remove it. _Test:_ "cannot veto the rules" in `packages/engine/test/engine.test.ts`.
- **Injected text never lowers a verdict.** _Test:_ the principles test runs every injected/clean pair against a fully compromised model. The eval also reports pair violations and the CI gate fails on any.
